# 「设计台」个人工作台 · 设计方案 v1.0

> 载体：DeepSeek Harness 插件（包名 `designer-desk`，形态 `bundle-client`）
> 使用者：室内设计师（单人使用，无账号体系）
> 文档状态：**策划待确认**（阶段 ① 需求捕获 → 阶段 ② 形态决策）

---

## 0. 一句话定义

把室内设计师的**全流程业务**收进一条「项目管线」的桌面前置工作台：
客户从线索到结项只有一条主线，今天该干的事自动浮到最上面，效果图直接在插件里调本机 ComfyUI 出，副业与娱乐隔到另一个 Tab，不干扰主业务。

---

## 1. 需求解码：11 项工作 → 4 条链

用户原话列的 11 件事看上去很散，其实全部挂在四个链条上。**这是整个方案的地基**——模块不是按「事情」切的，是按「链」切的。

| 链 | 用户原话 | 本质 | 最大的坑 |
|---|---|---|---|
| **A. 获客转化链** | 整理客户资料、预约量房、对接需求、设计方案、报价、签合同、预约到店、选材 | 单个客户项目的阶段推进 | 报价发出去没回音、该回访时忘了 |
| **B. 交付链** | 效果图、整理 PPT 汇报、关注工地进度、安排材料进场、全网找参考图 | 交付物的产出与节点不脱期 | 出图/找图吃掉大量时间；工地节点靠脑子记 |
| **C. 创作链** | 每天更新公众号文章、写小说 | 日更不断更 | 断一天就断一周 |
| **D. 补给链** | 听 QQ 音乐、看小说、阅读电子书 | 输入与放松 | 被「管理感」破坏，最后干脆不用 |

### 三条核心设计判断

**判断 1：主轴必须是一条「项目管线」，不能是待办清单。**
泛用待办 App 失败的原因是把「事情」当实体。而设计师的所有事情都是**某个客户项目的派生物**：量房是「金地花园-1201」项目的量房，报价是它的报价。
所以本工作台的数据主键是 **项目**，待办是项目的自动产物。用户完成一个阶段 → 系统自动排出下一阶段的标准动作 → **不漏跟进**这件事从「靠记性」变成「靠结构」。

**判断 2：设计师最贵的两笔隐性成本是「找图」和「出图」。**
全网格找参考图 + 等效果图，一天能吃掉 3-4 小时。方案里必须有专门的**效果图工坊**（接本机 ComfyUI）和**素材库**，把这两件事从「翻浏览器」压成「填三个字段点一下」。

**判断 3：副业和娱乐必须物理隔离。**
公众号/小说是「生产」，听歌/读书是「消费」。把消费放进主工作台会污染专注度。方案把它们放在**独立的 Tab**，且娱乐区做成「轻入口」——不做数据管理，就一个跳转和一句「在读」。

## 2. 业务阶段模型（9 段）

设计行业通用的项目阶段，每一段都绑定了「标准动作 → 交付物 → 自动排出的下一个待办」。这张表是整个工作台的引擎。

| # | 阶段 | 标准动作 | 交付物 | 完成后自动排出 |
|---|---|---|---|---|
| 1 | 线索 | 记录客户资料 / 需求 / 预算 | 客户档案 | 📅 预约量房（+1 天） |
| 2 | 量房 | 上门量尺 + 拍照 + 现场确认需求 | 户型数据 + 现场照片 | 📐 出平面方案（+2 天） |
| 3 | 方案设计 | 平面 → 效果图 → 汇报 PPT | 方案 PPT + 效果图 | 💰 出报价（+1 天） |
| 4 | 报价 | 出报价单、发送、跟进 | 报价单 v1 | 🔔 跟进回访（+2 天） |
| 5 | 签约 | 合同 + 收款计划 | 合同 | 🏬 预约到店选材（+1 天） |
| 6 | 选材深化 | 陪同选材、确认主材 | 选材清单 | 📦 材料下单（+1 天） |
| 7 | 施工 | 节点巡检（水电/瓦/木/油/安装） | 巡检记录 + 照片 | 🔁 下次巡检（+3 天） |
| 8 | 安装验收 | 安装、验收、整改 | 验收单 | 🏁 结项（+2 天） |
| 9 | 结项回访 | 回访、要转介绍 | 客户口碑 / 案例 | — |

> 这套「推一下就走」的机制是本方案最核心的体验：**用户只需要点「推进到下一阶段」，不用自己想下一步该干嘛。**

## 5. 第 1 期详细设计（3 模块）

### M1 · 项目管线看板

- **视图 A｜看板**：按 9 阶段分列的卡片墙，每张卡片显示 `客户名 · 小区房号 · 阶段 · 下次行动 · 倒计时`，逾期红标。支持拖拽换阶段。
- **视图 B｜列表**：表格 + 排序（阶段 / 最近联系 / 金额 / 倒计时）。
- **客户档案抽屉**：姓名、电话、微信、小区、户型、面积、风格偏好、预算、家庭成员、禁忌项、沟通记录流水。
- **新建项目 3 步**：客户资料 → 房屋信息 → 需求（风格/预算/特别要求）。创建即自动生成第 1 条待办「预约量房」。
- **一键推进阶段**：点「推进」→ 记流水 → 自动排出下一阶段标准待办。

### M2 · 今日作战台（置顶区，铁律 5）

落地页最上方，四个分区按优先级排列：

| 分区 | 内容 | 交互 |
|---|---|---|
| 🔴 **逾期** | 所有 `dueAt < 今天` 且未完成的 | 一键完成 / 一键顺延到明天 |
| 🟠 **今天** | `dueAt == 今天` 的量房/到店/巡检/材料进场/回访 | 一键完成 / 改期 |
| 🟡 **三天内** | 快到期的（避免突然爆雷） | 一键顺延 |
| ⚪ **无期但挂着** | 报价后 N 天没跟进的客户（沉默项目唤醒） | 一键生成跟进待办 |

**昨天没做完的自动滚到今天，绝不凭空消失。**

### M3 · 效果图工坊（接本机 ComfyUI）

设计师的「印钞机」。详见 §7。

- **入口一**：项目卡片上的「出效果图」按钮 → 自动带入该项目的风格偏好与户型。
- **入口二**：命令 `/出图 金地花园-1201 客厅 奶油风 无主灯` → 对话里直接出图。
- **参数面板**：空间（客厅/餐厅/主卧/次卧/儿童房/厨房/卫生间/玄关）、风格（现代简约/奶油风/新中式/侘寂/法式/轻奢/原木/工业）、材质关键词、光照、出图比例、张数、种子。
- **结果墙**：缩略图网格 → 点开大图 → 「设为方案主图」「加入 PPT」「重出（换种子）」。
- **归档**：自动落到 `renders/{项目名}/{日期}/`，绑定项目。

## 6. 数据模型（本地 JSON 主库）

> **存储方案说明**：资料库（云端数据表）能力经检测**当前不可用**，因此第 1 期采用**本地方案**——DSH 插件 Node half 直接把数据落盘到本地目录，天然持久、多设备可通过导出/导入迁移。

```text
~/.designer-desk/
├── data.json          # 主库
├── data.bak.json      # 滚动备份（每次写入前替换）
├── config.json        # 配置（ComfyUI 地址、节点 id、目录、提醒开关）
└── renders/           # 效果图归档
    └── {projectId}/{YYYY-MM-DD}/xxx.png
```

主库结构（第 1 期实际启用加粗）：

```jsonc
{
  "customers": [ /* 客户档案：**id** name phone wechat community layout area style budget family taboo notes createdAt */ ],
  "projects":  [ /* 项目：**id** **customerId** **name** **stage(1-9)** **nextAction** **nextActionAt** amount signDate logs[] createdAt updatedAt */ ],
  "tasks":     [ /* 待办：**id** **projectId** **title** **type** **dueAt** **done** doneAt priority postponedFrom */ ],
  "renders":   [ /* 效果图：**id** **projectId** prompt space style seed workflowId outputPath createdAt score */ ],
  "sites":     [ /* 工地：projectId node status plannedAt doneAt photos[] */ ],
  "materials": [ /* 材料：projectId name brand spec price qty supplier arriveAt status */ ],
  "refimages": [ /* 参考图：id url thumb tags[] score source projectId */ ],
  "quotes":    [ /* 报价：projectId items[] total version sentAt status */ ],
  "contracts": [ /* 合同：projectId amount signDate plan[] received[] */ ],
  "contents":  [ /* 内容：id type(公众号/小说) title status words publishAt link */ ],
  "reading":   [ /* 在读：id title author type status progress */ ]
}
```

**数据安全（铁律 2）**：
- 每次写入前自动滚动备份到 `data.bak.json`
- 首屏提供「导出 JSON 备份」「导入恢复」（不藏进设置里）
- 清空数据需二次确认弹窗
- 数据积累到 30 条时顶部温和提示备份

## 7. ComfyUI 集成方案（本方案的技术重点）

### 7.1 定位

工作台**不重复造 ComfyUI**，只做两件 ComfyUI 不做的事：**① 把项目上下文注入工作流**，**② 把结果归档回项目**。

### 7.2 调用链路

```
用户填参数（空间/风格/材质/比例/张数）
   ↓
Node half 把参数注入工作流 JSON（API 格式）
   ↓
POST http://{comfyHost}:8188/prompt   → 拿 prompt_id
   ↓
轮询 /history/{prompt_id}  或  连 /ws 拿实时进度
   ↓
ComfyUI 输出图片 → 拷贝到 renders/{projectId}/{日期}/
   ↓
写入 renders 表、绑定项目、生成缩略图
   ↓
工作台结果墙展示 / 一键放进方案 PPT
```

### 7.3 参数注入的两种方式（推荐 A，B 兜底）

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 按节点 ID 注入**（推荐） | 设置面板配置：正向提示词节点 ID、种子节点 ID、宽高节点 ID、（可选）输入图节点 ID | 用户不用改工作流，最稳 | 用户要去 ComfyUI 界面查一次节点编号 |
| B. 占位符替换 | 用户把工作流里的提示词写成 `{{prompt}}`，导出后插件做字符串替换 | 配置最简单 | 需要用户改工作流，节点一改就失效 |

### 7.4 必须避开的坑

> ⚠️ **ComfyUI 导出的工作流必须是「API 格式」**（界面右上角 `Workflow → Export (API)`），普通 UI 格式的 JSON 无法提交给 `/prompt`。这是接入时踩坑率最高的一点。
>
> ⚠️ **ComfyUI 要和 DSH 在同一台机器，或至少网络互通**。默认地址 `http://127.0.0.1:8188`。
>
> ⚠️ **出图是长任务**（30 秒 ~ 5 分钟），HTTP 接口必须返回 `prompt_id` 后异步轮询，不能同步阻塞等待。

### 7.5 降级策略（铁律：不崩）

| 情况 | 表现 |
|---|---|
| ComfyUI 未启动 | 按钮置灰 + 提示「ComfyUI 未连接，点击查看启动方式」，其余模块照常可用 |
| 未配置工作流 | 引导式弹窗：教用户导出 API 格式 JSON + 填节点 ID |
| 出图失败 | 保留 prompt 参数，给「重试」按钮，不丢用户的输入 |
| 网络断开 | tasks/customers 等主业务数据完全不受影响（本地存储） |

## 8. DSH 插件形态与能力映射

### 8.1 形态决策

| 决策项 | 结论 | 依据 |
|---|---|---|
| **形态** | `bundle-client` | 需要工作区页面 + 设置面板 + 状态栏，必须有浏览器 client half |
| **分发方式** | git 源（默认推荐，`lib/` 构建产物入库） | 便于迭代与回滚 |
| **包管理器** | pnpm（默认推荐） | — |
| **目标 profile** | `web` | DSH Web 工作区 |

### 8.2 能力面映射（配方装配表）

| 工作台功能 | 能力面 | 实现侧 | 装配配方 |
|---|---|---|---|
| 工作台页面（今日 / 项目 / 效果图 三 Tab） | 工作区 / 仪表盘 | client | `dashboard-workspace` |
| 设置（ComfyUI 地址、节点 ID、归档目录、提醒开关） | 浏览器设置面板 | client + node | `settings-panel` |
| 顶栏「今日 N 项待处理」角标 | 状态栏组件 | client | `status-badge` |
| 项目 / 客户 / 待办 CRUD 接口 | HTTP 接口 | node | `http-api` |
| 项目数据服务（供其他插件或 AI 调用） | 对外提供服务 | node | `service-provider` |
| 每日 08:30「今日待处理」摘要；巡检 / 预约 / 回访到期提醒 | 事件订阅 + 定时任务 | node | `event-task` |
| `/今日`、`/加项目`、`/出图`、`/推进` 等命令与工具 | 命令 / 工具 | node | `command-tool` |
| ComfyUI 提交与轮询（HTTP 调本机服务） | MCP 桥接 / HTTP | node | `command-tool` + `http-api` |
| 效果图 / 参考图归档与展示 | 静态资源托管 | node | capability-map 静态资源 |

**合并规则**：Node half 的 `inject` 取并集 → `['webServer']`；所有注册统一放进 `ctx.effect()` 并返回 disposer；client half `inject` → `['slots', 'ui']`。

### 8.3 合同关键点（必守）

- `package.json#name` == `cordis.patch.yml` insert 的 id/name == client ModuleLoader 的 id == **`designer-desk`**，三者必须一致。
- `type: module`、`main: lib/index.js`、`exports` 含 `"."` `"./client"` `"./cordis.patch.yml"` `"./package.json"`。
- **禁止声明 `@deepseek-ai/*` 依赖**（DSH profile 已提供）。
- React 四个包（`react` / `react/jsx-runtime` / `react-dom` / `react-dom/client`）必须 external，否则 `Cannot read properties of null (reading 'useState')`。

### 8.4 冒烟功能（先跑起来）

1. 命令 `/designer-desk hello 世界` → 返回打招呼文本
2. 路由 `GET /designer-desk/health` → `{ ok: true }`
3. 工作区出现「设计台」页面，并渲染 3-5 条示例项目（**含 1 条逾期**）
4. 状态栏出现「今日 N 项」徽标

**冒烟判定：命令有返回 + 路由 200 + 页面有数据 + 徽标可见 = 全链路通了，再填业务。**

## 9. UI / 视觉

### 9.1 导航结构

```
PC：左侧竖栏（今日 / 项目 / 效果图 / …后续期次追加） + 右侧主区
移动 & 窄屏（<768px）：主区单列堆叠 + 底部 Tab 栏
```

### 9.2 视觉基调

设计师是审美敏感人群，界面必须**克制、有质感**，不能花。

| 元素 | 取值 |
|---|---|
| 底色 | `#FAF8F5`（米白，比纯白柔和） |
| 卡片 | `#FFFFFF` + `1px solid #E8E3DC` + 圆角 12px |
| 主文字 | `#1F1D1A`（墨黑，不用纯黑） |
| 次文字 | `#8A837A` |
| **主色** | `#B85C38`（赭橙，点睛色，只用于主动作按钮与选中态） |
| 状态色 | 逾期 `#C0392B` / 临近 `#C0872B` / 正常 `#4A6B57` |
| 字体 | `-apple-system, BlinkMacSystemFont, "PingFang SC", "Segoe UI", Roboto, sans-serif` |

### 9.3 移动适配（必备）

- 按钮最小点击区 **44×44px**
- 输入框字号 **≥16px**（否则 iOS 自动放大页面）
- 表格窄屏改卡片列表或横向滚动
- 适配底部安全区：`padding-bottom: env(safe-area-inset-bottom)`
- 视觉：工作台渲染在 DSH Web 内，**关键样式一律内联**（宿主 CSS 可能覆盖 class）

## 10. 风险与降级

| 风险 | 影响 | 对策 |
|---|---|---|
| ComfyUI 工作流格式不对（非 API 格式） | 出图全流程失败 | 设置面板内置图文引导 + 提交前校验 `prompt` 字段 |
| 文件系统写入权限 | 数据无法持久 | 首次启动自检目录可写，失败则引导改目录 |
| Node half 变更不生效 | 改完没反应 | 明确文档：改 `src/` → `pnpm run bundle` → **重启 web**（ESM 缓存不热更） |
| 模块越加越多导致失焦 | 用不起来 | 严格执行分期（§4），每期 ≤3 模块 |
| 公众号自动发布 | 微信个人号无开放接口 | 定位为「日更台」：选题库 + 发布日历 + 草稿 + 一键复制，**不承诺自动发布** |
| QQ 音乐 / 阅读 | 无合法 API | 定位为「轻入口」：本地唤起客户端 + 记录在听/在读，不做数据抓取 |
